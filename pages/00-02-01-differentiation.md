# 0.2.1. 수치미분  

혹시 미분의 정의를 기억하시나요? 미분하는 법은 기억나는데 정의는 가물가물하시다구요? 바로 이렇게 정의했었습니다.  

$$
\frac{d}{dx} f(x) = \lim_{h \to 0} \frac{f(x+h) - f(x)}{h}
$$

아하! 이제 좀 기억이 나시죠? 여기서 중요한 것은 바로 극한입니다. 극한이라는 것의 정의(엡실론-델타 논법을 썼었죠.)가 수학적으로 엄밀하긴 하지만 컴퓨터로 계산하는 데 그 정의를 쓸 수는 없거든요.  
그러면 컴퓨터는 미분을 어떻게 하는 걸까요? 일단 극한은 잊어버리고 뒤에 있는 분수만 볼까요? 여기에서 $h$에 우선 아주 작은 값을 넣어봅시다.  

$$
\frac{d}{dx} f(x) \approx \frac{f(x+h) - f(x)}{h}
$$

이런 식으로 계산하는 것을 **유한차분(finite difference)**이라고 부릅니다. $h$를 양수라고 놓으면 전진차분(forward difference), 음수라고 놓으면 후진차분(backward difference)라고 부릅니다.  
그런데 이렇게 구해도 충분히 정확한 값이 나올까요? 한번 확인해봅시다.  

## 차분과 오차  

$f(x) = \sin(x)$의 $x=1$에서의 미분값을 구해보겠습니다. 원래 사인 함수를 미분하면 코사인이 되죠. 그러니까 정답은 $\cos(1)=0.5403023\ldots$가 나와야 합니다. $h$의 값을 점점 작게 하면서 정답에 얼마나 가까워지는지 계산해봅시다.
```python
import numpy as np

f = np.sin
df = np.cos
x0 = 1.0
exact = df(x0)

print(f"정확한 값         = {exact:.10f}")

for h in [0.1, 0.01, 0.001, 0.0001]:
    d = (f(x0 + h) - f(x0)) / h
    print(f"h ={h:6.0e}: 근사값 = {d:.10f}, 오차 = {abs(d - exact):.3e}")
```
```
정확한 값         = 0.5403023059
h = 1e-01: 근사값 = 0.4973637525, 오차 = 4.294e-02
h = 1e-02: 근사값 = 0.5360859810, 오차 = 4.216e-03
h = 1e-03: 근사값 = 0.5398814804, 오차 = 4.208e-04
h = 1e-04: 근사값 = 0.5402602314, 오차 = 4.207e-05
```
$h$를 10분의 1씩 줄일 때마다 오차도 약 10분의 1씩 줄어드는군요. 오차가 $h$에 비례한다는 뜻입니다. 이런 경우를 **1차 정확도(first-order accuracy)**를 가지는 근사라고 부르고, $O(h)$라고 씁니다.  
나쁘지는 않지만 오차를 더 빠르게 줄일 수 있는 방법이 있을까요? 바로 앞뒤를 같이 보면 됩니다! 그러니까 전진차분과 후진차분을 같이 보는 거죠.  

$$
\frac{d}{dx} f(x) \approx \frac{f(x+h) - f(x-h)}{2h}
$$

이것을 **중심차분(central difference)**라고 부릅니다. 이 방법을 쓰면 오차가 얼마나 더 빠르게 줄어들까요?
```python
for h in [0.1, 0.01, 0.001, 0.0001]:
    d = (f(x0 + h) - f(x0 - h)) / (2 * h)
    print(f"h ={h:6.0e}: 근사값 = {d:.10f}, 오차 = {abs(d - exact):.3e}")
```
```
h = 1e-01: 근사값 = 0.5394022522, 오차 = 9.001e-04
h = 1e-02: 근사값 = 0.5402933009, 오차 = 9.005e-06
h = 1e-03: 근사값 = 0.5403022158, 오차 = 9.005e-08
h = 1e-04: 근사값 = 0.5403023050, 오차 = 9.004e-10
```
이번에는 $h$를 10분의 1씩 줄일 때마다 오차가 100분의 1씩 줄어듭니다! 즉, 오차가 $h^2$에 비례하는 2차 정확도, $O(h^2)$를 가지는 근사가 되었습니다.  
계산량은 똑같은데 오차가 줄어드는 속도가 제곱으로 빨라졌습니다. 와 진짜 좋네요! 앞으로 중심차분을 계속 써야겠어요.  

왜 이렇게 오차가 빠르게 감소하는 지는 **테일러 전개(Taylor expansion)**을 통해 설명할 수 있습니다. 전진차분 하나만 사용했을 때에는 2차 항이 그대로 오차로 남지만, 중심차분을 사용하면 2차 항이 상쇄되어 사라지거든요. 궁금하신 분들은 직접 계산해보셔도 좋습니다.  


## 반올림 오차와 절단 오차

그러면 $h$를 엄청나게 작게 줄이면 오차가 0에 가까워지겠네요? 어디까지 작아질 수 있는지 한 번 봅시다.
```python
for h in [1e-2, 1e-4, 1e-6, 1e-8, 1e-10, 1e-12]:
    d = (f(x0 + h) - f(x0 - h)) / (2 * h)
    print(f"h ={h:6.0e}: 오차 = {abs(d - exact):.3e}")
```
```
h = 1e-02: 오차 = 9.005e-06
h = 1e-04: 오차 = 9.004e-10
h = 1e-06: 오차 = 2.772e-11
h = 1e-08: 오차 = 2.581e-09
h = 1e-10: 오차 = 5.848e-08
h = 1e-12: 오차 = 1.227e-05
```
엥? $h$의 값이 $10^{-6}$까지 줄어들 때까지는 오차가 작아지다가, 그 이후로는 오히려 더 커집니다. 심지어 $h=10^{-12}$부터는 $h=10^{-2}$일 때보다도 오차가 커졌습니다. 이상하다 분명히 극한에서 $h$를 0으로 보내야 미분이 되는데... 무엇이 잘못되었을까요?

범인은 0.1.2.에서 잠깐 스쳐갔던 그 녀석입니다. `15.000000000000002` 기억하시나요? 컴퓨터는 무한한 정밀도로 실수를 표현할 수 없기 때문에 어쩔 수 없이 자릿수를 제한해서 저장합니다. 10진법으로는 유한하더라도 2진법으로 변환하면 무한소수가 되는 경우가 많거든요. 이렇게 지저분한 숫자들이 남게 되면 아주 작은 수들끼리 계산을 할 때 오히려 오차가 증폭됩니다. 이렇게 발생하는 **반올림 오차(round-off error)**와, 우리가 $h$를 점점 작게 만들면서 개선하려고 했던 **절단 오차(truncation error)**가 서로 *가슴이 웅장해지는 싸움*을 하고 있는 것입니다.  
두 오차가 서로 정반대로 움직이니 가운데 어딘가에 최적점이 있겠죠. 그림으로 그려보면 확실하게 알 수 있습니다.  

```python
import matplotlib.pyplot as plt

hs = np.logspace(-15, -1, 400)
err_f = np.abs((f(x0 + hs) - f(x0)) / hs - exact)
err_c = np.abs((f(x0 + hs) - f(x0 - hs)) / (2 * hs) - exact)

fig, ax = plt.subplots(figsize=(8, 5))
ax.loglog(hs, err_f, lw=2, label="forward difference")
ax.loglog(hs, err_c, lw=2, label="central difference")
ax.set_xlabel("h")
ax.set_ylabel("error")
ax.grid(alpha=0.3, which="both")
ax.legend()
plt.show()

print("오차가 가장 작은 h =", hs[np.argmin(err_c)])
```
![절단 오차와 반올림 오차](image-10.png)
```
오차가 가장 작은 h = 5.239601353002634e-06
```

V자 모양이 나오죠. 오른쪽이 절단 오차 구간이고, 왼쪽이 반올림 오차 구간입니다. 두 선이 만나는 골짜기가 최적점이 되겠네요. 왼쪽의 반올림 오차 구간은 컴퓨터의 특성상 노이즈가 많이 생겨서 어떤 계산을 하느냐에 따라 오차가 항상 같게 나오지는 않습니다. 중심차분의 경우에는 최적값이 대략 $10^{-5}~10^{-6}$ 구간에서 존재한다고 보면 됩니다.  

[[TIP]]
실제로 계산을 할 때는 매번 최적값을 찾을 필요는 없습니다. 중심차분을 쓸 때는 대체로 $10^{-5}~10^{-6}$ 구간의 값을 쓰면 오차를 최대한 줄일 수 있습니다. 하지만 이 구간에서는 위 그림에서 보이는 것처럼 노이즈가 많이 생기니 '무조건 작은 $h$ 값을 써야 좋다!' 라고 생각하시면 안 됩니다. 이건 수치계산 전반에 해당하는 이야기니 앞으로 이렇게 무언가 잘게 나눌 일이 있을 때에는 기억하시면 좋습니다.
[[/TIP]]


## 2차 차분

1차 미분을 차분으로 계산해보았는데요, 그럼 2차 차분은 어떻게 될까요? 슈뢰딩거 방정식을 풀 때 2차 미분이 등장하거든요. 2차 중심차분은 다음과 같이 계산할 수 있습니다.

$$
\frac{d^2}{dx^2}f(x) \approx \frac{\frac{f(x+h) - f(x)}{h} - \frac{f(x) - f(x-h)}{h}}{h} = \frac{f(x+h)-2f(x)+f(x-h)}{h^2}
$$

2차 차분도 한 번 계산해봅시다. 위에서 썼던 사인 함수를 그대로 가져와보죠. $\sin(x)$의 2차 미분은 $-\sin(x)$였습니다.
```python
h = 1e-4
d2 = (f(x0 + h) - 2 * f(x0) + f(x0 - h)) / h**2

print(f"정확한 값  = {-f(x0):.12f}")
print(f"근사값     = {d2:.12f}")
```
```
정확한 값  = -0.841470984808
근사값     = -0.841470981783
```

소수점 8번째 자리까지 맞네요. 2차 차분을 계산할 때 분모에 $h^2$이 있어 반올림 오차를 줄이기 위해 조금 더 큰 값인 $10^{-4}$을 사용했습니다.  
위 식에서 함수값의 계수로 나타난 $1, -2, 1$이라는 숫자의 조합을 기억해주세요. 0.2.3.에서 다시 만나게 됩니다.

## 정리하며

미분을 컴퓨터로 계산하는 방법을 살펴보았습니다. 극한을 떼어내고 차분으로 바꿔서 계산하니 뺄셈과 나눗셈만 있으면 됩니다. 다음 절에서는 적분을 계산하는 방법에 대해 살펴보겠습니다.
